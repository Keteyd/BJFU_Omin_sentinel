## MPC 要解决什么

由一个优化器同时考虑两个 yaw，目标包括：

1. 优先跟踪瞄准航向，抑制外部扰动。
2. 在可行情况下减少大 yaw 相对车体的转动。
3. 小 yaw 接近行程边界时，由大 yaw 分担转动，恢复小 yaw 的活动余量。
4. 同时考虑两轴惯性耦合、执行器响应和有限输出能力。

大 yaw “少动”通过代价函数表达，不是把它的电机输出关掉。为了抵消小 yaw 的反作用，大 yaw 可能需要较大的保持力矩，但关节角度变化很小。

这些目标使用有限权重进行权衡，目前不是严格的逐级优先优化。权重和模型都还不是实车定稿。

## 模型如何表示

当前原型包含六个状态：

```text
x = [大 yaw 关节角, 小 yaw 关节角,
     大 yaw 关节角速度, 小 yaw 关节角速度,
     大 yaw 执行器状态, 小 yaw 执行器状态]

M × 关节角加速度 + D × 关节角速度 = K × 执行器状态
T × 执行器状态变化率 = 电机驱动输入 - 执行器状态
```

每个关节都有二阶机械动力学。`M` 是包含非对角项的惯性矩阵，用来描述两个关节之间的耦合；另外两个状态描述执行器滞后。这里并没有把整套双轴系统视为一个一阶系统。

注意三个区别：

- 执行器状态不是实测电流或力矩。当前驱动单位也不能直接当作牛米。
- 当前 `M`、`D`、`K`、`T` 都是假定数值，不能根据仿真结果推断实车惯量。
- 六状态只是起点。如果实测表明需要摩擦、输入延迟、扰动或其他状态，会调整模型阶次。

平面仿真用“大关节角 + 小关节角”表示相对固定车体的航向。你的实车存在车体倾斜、Pitch 转动以及两轴平行但不共轴等情况，实际航向必须结合 IMU、编码器标定和坐标变换；不能直接把陀螺仪 Z 轴当成任何姿态下的航向角速度。非共轴距离也会影响动力学，后续视觉近距离目标的视线换算还需要相机安装几何信息。

## 小 yaw 的限位怎样处理

限位沿用已测定的真实外观中位，不取左右机械极限的算术中点。

| 项目 | 当前值 |
| --- | --- |
| 中位编码器 | 6816 counts，即 299.53125° |
| 负方向软限位 | -56.677734375° |
| 正方向软限位 | +29.080078125° |
| 仿真舒适活动区 | 两侧各取对应软行程的 70% |

处理方式：

- 预测位置必须满足非对称软限位，不通过放松约束允许越界。
- 对未来预测位置增加 0.1° 的内侧数值裕度，避免求解误差导致贴边越界。这不是实测安全裕度，也没有改变固件限位。
- 超出舒适活动区只增加代价，仍然允许小 yaw 使用剩余行程。这样大 yaw 会逐渐分担运动，而不是每次都强制小 yaw 回中。
- 预测末端要求小关节相对角速度为零，作为规划制动的条件；这还不是完整的可停车区域或稳定性证明。
- 大 yaw 不设置角度边界，也没有新增硬性速度上限。角度采用连续多圈表示，不能每次都折回 ±180°。
- 仿真保留有限驱动输入：大 yaw 30、小 yaw 6，单位为现有软件驱动单位，不是力矩。这里没有提高实车输出上限。

如果状态过期、越界、求解超时或问题无可行解，原型返回 `command=None`，不会沿用上一次输出。**这只是离线拒绝结果，尚不是已实现的实车停车策略。**

## 我们怎样做双轴动力学辨识

最新进度见 [辨识集成与现场步骤](IDENTIFICATION_CORE.zh-CN.md)：按固定车体、常用 Pitch 姿态、无相机负载继续。协议、输出控制权和同步记录已接入，离线测试与 AC6 构建通过；尚未烧录或执行实车试验，下一步先做上置静态检查。

辨识的直观含义是：**记录两个电机收到什么驱动，以及两轴和 IMU 随后怎样运动，从这些记录估计可预测实车响应的模型。**

必须同时关注四条作用关系：

| 输入 | 需要观察的响应 |
| --- | --- |
| 大 yaw 驱动变化 | 大 yaw 自身运动 |
| 大 yaw 驱动变化 | 小 yaw 和 IMU 的响应 |
| 小 yaw 驱动变化 | 小 yaw 自身运动 |
| 小 yaw 驱动变化 | 大 yaw 和 IMU 的响应 |

现有松杆记录中，大 yaw 输入始终为零，输入矩阵秩为 1。它能用于检查小 yaw 的局部响应，但不足以辨识两路电机的完整作用。

这里“分别激励”指分别给两路施加可区分的试验信号，**不等于必须拆开机械连接或关闭另一个轴**。另一轴闭环保持时也可能产生抵消输出，所以始终记录两路实际输出，而不是假定未测试的一路输出为零。

### 第一步：准备专用辨识模式，暂不运动

这一步由我完成代码设计、实现和静态验证，你不需要计算矩阵。

已具备：同步记录两轴与 IMU、上置安全模式、软限位、500 Hz 缓存下载。

本次已实现、仍需现场验证的内容：

- 在专用辨识模式中管理两轴输出权限，不能只把 `BIG_YAW_OUTPUT_INHIBIT_TEST` 改成零就开始测试。
- 明确辨识期间两个轴各自的参考来源，避免旧的自动跟随协调逻辑和辨识目标同时写入参考。
- 保留已调好的参数作为基线，记录所使用的闭环结构。优先设计在受控闭环下的试验，不直接开放最大电压输出。
- 在主控端同步试验信号与缓存，记录参考、注入信号、最终驱动、限幅状态和实际时间。仅靠聊天提示或 PC 发包时间不足以精确对齐。
- 制定超时、数据失效、急停、超行程等退出条件；停止激励后的处理也必须明确。不能把关闭串口当作停车。
- 增加 250 Hz、4 秒、1001 点紧凑记录，与原 500 Hz/512 点缓存互斥复用；保存两路软件驱动、运动观测、参考偏移和配置元数据。它不包含执行器内部状态，数据细节和损失的精度见集成文档。

### 第二步：确定本轮机械状态

实测前由你确认现场，我读取状态核对：

- 车体固定，轮组、Pitch 及其他机构不会在使能时造成意外移动。
- 小 yaw 靠近已标定的外观中位，两侧有足够余量，线缆不干涉。
- 保留实际工作负载，记录相机、支架、线缆和 Pitch 姿态；负载变化会改变模型。
- 能随时上置退出，人员不接触正在运动的关节。

主控安全状态不是实物间隙的替代品。初始工况确定后再规定幅度、输出、频带和持续时间，文档不预先授权任何具体运动。

### 第三步：采集可区分的双路响应

先按一种可预测、时间受限的信号方式取得清晰响应，再根据数据扩展所覆盖的动态范围。可考虑带限多正弦或设计过的脉冲序列，具体形式在辨识模式实现时确定。

第一组主要变化大 yaw 的试验参考，第二组主要变化小 yaw 的试验参考；两组都同步记录两路最终驱动和全部运动响应。必要时再使用两路可区分的联合信号。正反方向与不同姿态的覆盖属于模型有效范围验证，不是重新排查已正常的小 yaw。

每组的分工：

1. 我检查程序版本、参数快照、遥测状态和采集准备情况。
2. 你确认现场安全，按当次明确说明进入试验状态。
3. 主控按已批准的时序执行、记录，异常时禁用输出并锁定控制权；代码已实现，实车链路尚待验证。
4. 你确认回到上置；我再核对实时状态并分析数据，不连续自动开始下一组。

如果采用闭环试验，不能只拟合“参考角到反馈角”就把它当成“电机驱动到运动”的裸对象模型。闭环反馈和噪声相关性要在辨识方法中处理，实际驱动、试验参考和原有控制结构都需保留。

### 第四步：拟合并检查真实模型

由我完成离线处理：

- 按主控时间对齐数据，检查采样连续性、反馈新鲜度、编码器跨圈、限幅及试验是否触碰边界。
- 建立统一的角度、角速度坐标，保留两轴耦合，必要时加入摩擦、延迟或其他状态。
- 评估输入是否提供足够信息；秩为 2 也不代表所有动态参数都可辨识。
- 使用不同记录分别做参数估计和验证，比较多步预测、运动方向、制动趋势和残差。
- 若预测误差集中在特定姿态、方向或速度区间，只补充针对性数据，不反复无目的调 PID。

独立验证集用于检验预测能力，不能只看拟合原始训练记录的误差。[数据估计与验证的参考说明](https://www.mathworks.com/help/ident/select-data-for-estimation.html)。

### 第五步：回放、影子运行，再接管

先将辨识模型代入 MPC，使用记录验证预测和约束。之后考虑实车影子模式：只算建议输出，不控制电机，与实测比较。

在实时性、状态估计、制动余量及异常退出得到验证后，再单独安排接管试验。到那一步才讨论降低原有 PID 的职责或替换相应控制环，当前不拆掉已能工作的闭环。
