## 采集位置与含义

固件路径相对于 `AGVSentinel_v10090/AGVSentinel_gimbal`。

| 对象 | 实际来源 | 新增证据 |
| --- | --- | --- |
| 大 yaw 指令 | `Can_SendMessage`，CAN1 标准数据帧 `0x2FF`，字节 0/1 | 实际待发送的有符号 16 位编码值 |
| 小 yaw 指令 | 同上，CAN2 `0x1FF`，字节 2/3 | 同上 |
| 发送结果 | `HAL_CAN_AddTxMessage` 返回值、对应硬件邮箱 TSR | 入队成功/失败、完成成功、仲裁或发送错误、终止及待完成数量 |
| 大 yaw 反馈 | CAN1 `0x209`，DLC 8 | 原始编码器、rpm、反馈电流及软件接收时间 |
| 小 yaw 反馈 | CAN2 `0x206`，DLC 8 | 同上 |

每次发送尝试之前更新指令序号与积分；等待结束后记录 HAL 入队结果。
`integral_raw_us` 表示**尝试发送的指令**在软件时间上的保持积分，失败尝试也计入这条历史，
并同时保留失败状态。它不表示电机实际收到的输入，更不表示力矩积分。
`queued` 只表示 HAL 接受了发送请求；`completed` 表示观察到该邮箱的 TXOK，
并不证明电机内部已经执行或反馈电流与该条指令一一对应。

TX 中断配置和优先级保持原设置；采集期间，在每次 HAL 发送前（包括同总线非 yaw 帧）
以及采样边界轮询并清除完成标志，避免邮箱复用后错误归属到前一条 yaw 指令。
Pitch 的 DM 发送路径通过 `Can_SendMessageNoWait` 接入相同观察逻辑，保留单次立即入队行为。
`complete_us` 是软件观察 TSR 完成标志的时间，不是总线边沿时间。
同一次轮询可能观察到多个完成；`complete_sequence` 是最后处理的成功槽位序号，
不保证是已完成序号的最大值，也不能据此恢复总线完成顺序。
ESR 警告/被动错误/总线关闭用区间标志汇总，未记录逐次总线错误事件时间。

反馈在进入现有电机解码逻辑前复制原始值。电流保留协议有符号原始单位，
不换算安培或关节力矩。反馈时间是软件接收处理时间，不是电机内部 ADC 采样时间。

## 统一时间与区间边界

进入 BASELINE 时开启追踪，以 DWT CYCCNT 差值累积微秒，epoch 从 0 开始；
不重置共享 CYCCNT。每次访问均在短临界区内，保留余数，并处理 32 位周期计数回绕。
使用当前 `SystemCoreClock`（本目标 168 MHz）换算，采集期间要求核心时钟不切换。
名义 4 ms 采样点仍在 yaw 输出之后；IMU/原电机快照和 CAN 区间快照在同一临界区读取。
不同传感器的物理采样时刻并不因此相同。

- `trace_us`：当前区间右边界，距本次追踪开始的微秒数。
- `interval_us`：距上一边界的实际时长；第一条为从 epoch 到首次快照的时长。
- `known_us`：该区间中，已经知道至少一次实际发送尝试值的覆盖时长。
  首区间可能不完整或为零，不能假定追踪开始前的电机输入为零。
- `integral_raw_us / known_us`：覆盖部分的时间加权尝试指令均值；无覆盖时 CSV 留空。
- 每次快照清空区间积分、计数、等待总时长和故障标志，保留末指令、反馈与最后观察到的成功结果。
  极值包括边界上的指令更新，即使它对本区间积分的持续时间为零。
- 终止时先保留最后快照再关闭追踪。末条 `pending` 可以非零，表示截至采样边界尚未观察到完成；
  不等待排空再伪造一个全完成结果，终止后的发送不在本次记录中。

## 二进制协议

所有多字节字段均为小端；原始 CAN 载荷在采集入口按电机协议的大端解码。
原控制帧仍是 16 字节、CRC8；profile 与 metadata 使用版本 3 分片。
数据帧改为以下固定 163 字节：

```text
FF 3F | trial_id:u32 | sample_sequence:u16 | record:152 bytes | CRC16:u16 | 0D
```

CRC16-CCITT：初值 `0xFFFF`，多项式 `0x1021`，无反射/末异或，覆盖前 160 字节。
`sample_sequence` 从 1 连续递增至 5001；每帧携带 trial ID。
152 字节记录由旧 48 字节测量快照、`trace_us:u32`、`interval_us:u32`、
大 yaw 48 字节诊断、小 yaw 48 字节诊断组成。

每轴字段顺序如下，偏移相对于该轴的 48 字节块：

| 偏移 | 类型 | 字段 | 含义 |
| ---: | --- | --- | --- |
| 0 | u32 | sequence | 本次追踪的累计尝试序号 |
| 4 | u32 | attempt_us | 最近一次尝试时间 |
| 8 | i32 | integral_raw_us | 本区间尝试指令保持积分 |
| 12 | u32 | feedback_us | 最近一次原始反馈接收时间 |
| 16 | u32 | complete_sequence | 最后处理的成功完成对应尝试序号 |
| 20 | u32 | complete_us | 上述完成标志的软件观察时间 |
| 24 | u16 | known_us | 本区间指令覆盖时长 |
| 26, 28, 30 | i16 × 3 | minimum, maximum, command | 区间最小、最大与末指令 |
| 32 | i16 | current | 原始反馈电流 |
| 34 | u16 | encoder | 原始编码器计数 |
| 36 | i16 | rpm / CSV feedback_rpm | 原始反馈 rpm，CSV 加轴前缀，避免与旧快照列重名 |
| 38 | u16 | wait_us | 区间内发送尝试到 HAL 调用前的累计软件耗时，包括等待和调度延迟 |
| 40 | u16 | flags / CSV trace_flags | 下表标志 |
| 42–47 | u8 × 6 | attempts, queued, completed, failed, errors, aborted | 区间次数 |

`failed` 是 HAL 入队失败；`errors` 是已归属邮箱的仲裁/发送错误；`aborted` 是未见成功或错误位的完成终止。
这些是不同阶段的计数，完成可能属于前一区间已入队的请求。

| 位 | 含义 |
| --- | --- |
| 0 | 本次追踪已见发送尝试，末指令有效 |
| 1 | 本次追踪已见反馈，反馈字段有效 |
| 2 | 8 位区间计数发生饱和，数值仅作下界 |
| 3 | 积分或覆盖时长饱和 |
| 4 | 等待总时长饱和 |
| 5 | 原有 5000 次邮箱等待循环耗尽（不是 5000 微秒保证） |
| 6 | 邮箱归属冲突 |
| 7 | 观察到 ESR 警告/被动错误/总线关闭 |
| 8–9 | 当前归属该轴的待完成邮箱数，0–3 |

计数和积分溢出均饱和并置位，禁止回绕后冒充完整数据。
原始反馈缺失时字段为零，但必须依据有效位识别，不能把它解释成真实零电流。

## 带宽、缓冲与质量控制

波特率保持 460800，8N1 可用线速 46080 字节/秒；163 × 250 = 40750 字节/秒，
仅数据占用约 88.4%，剩余用于状态、描述信息和调度间隙。
一帧在线时间约 3.54 ms，软件启动延迟和临界区开销仍需实板测量。

环形缓冲 320 条，共 48640 字节，复用原静态 union，未扩大原约 48 KiB 的共享采集存储。
名义容量约 1.28 秒；流进度超时保护更早生效（300 ms），不能把容量当成可容忍断线时长。
保留一个终止槽位；未收到连续解码回执的记录不能被覆盖。
UART DMA 使用独立静态 163 字节发送缓冲，忙时直接返回，不改写正在传输的数据。

新解码器验证版本、trial ID、连续样本序号、CRC、区间边界、指令覆盖、极值、积分范围和邮箱计数守恒。
结构/身份/CRC 错误在追加该条记录前抛出，CLI 不确认失败数据；状态故障仍保留到 CSV 并标记质量问题。
不因诊断异常静默丢弃整行。`report.json` 增加每轴计数总和、计数饱和、反馈年龄最大值、
待完成数量及覆盖缺失统计；计数饱和时总和不是精确总事件数。

固件 BENCH 资格会被计数/发送故障、后续区间缺失输入或反馈、非零尝试指令、
以及异常区间时长锁住。成功传完数据不自动 RELEASE，也不自动开始运动试验。
记录完整性、CAN 状态正常和动力学模型有效是分别需要验证的结论。
